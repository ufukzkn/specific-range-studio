## 3. Project Narrative to Preserve

The project is about:

> Modeling and comparing a fighter aircraft specific range performance dataset using traditional interpolation/numerical methods, XGBoost, and FT-Transformer, with attention to accuracy, runtime, memory, CPU, model size, and edge deployment suitability.

The narrative should be balanced:

- This is not “AI beats everything.”
- This is not “Transformer is always best.”
- This is a structured comparison of method families.

Correct high-level conclusions:

- **Cubic spline interpolation** is the strongest traditional/numerical interpolation method in the project’s traditional-method comparison.
- **XGBoost** is currently the strongest practical learned model for tabular accuracy and demo/deployment balance.
- **FT-Transformer** is the academic/deep-learning architecture candidate; it is important for explaining feature tokenization, attention, and tabular-transformer modeling, even if it does not beat XGBoost in the current measured setting.
- **Interpolation** is a deterministic reference/table family, not a learned model. It should not be scored as a learned-model accuracy competitor against a reference generated by itself.

## 4. Interpolation Role: Avoid This Common Mistake

The runtime default interpolation method is:

```text
Cubic Spline
```

Code location:

- `src/interpolation/specific_range.py`

Important implementation details:

- `DEFAULT_INTERPOLATION_METHOD = "spline"`
- `"spline"` is displayed as `Cubic Spline`
- other supported methods are `linear` and `newton`

In the UI/custom-input context, interpolation is used as a deterministic reference or “tahmini gerçek” value. Therefore:

- Do not compare cubic spline against itself and call it “0-error winner.”
- If comparing interpolation methods, use hold-out table nodes:
  - remove some known table points,
  - interpolate from remaining points,
  - compare predicted values to held-out true table values.

This distinction should be explicit in the final report.

Suggested wording:

```text
İnterpolasyon yöntemleri hold-out tablo noktaları üzerinde kendi aralarında değerlendirilmiştir. Uygulama arayüzünde ise kübik spline interpolasyonu, öğrenen modellerin çıktısını yorumlamak için deterministik referans aile olarak kullanılmıştır. Bu nedenle interpolasyon, XGBoost ve FT-Transformer ile aynı learned-model accuracy yarışına sokulmamıştır.
```

## 5. XGBoost and FT-Transformer Roles

### XGBoost

XGBoost is the practical learned-model baseline and current strongest learned predictor.

Use it as:

- practical ML predictor,
- low-latency demo model,
- strong tabular baseline,
- fair comparison point for FT-Transformer.

Do not frame XGBoost as a weak baseline. It is a strong method and often beats deep tabular models on medium-sized tabular datasets.

### FT-Transformer

FT-Transformer is the academic/architecture-focused method.

Use it to explain:

- feature tokenizer,
- numerical and categorical feature tokenization,
- Transformer encoder,
- multi-head self-attention,
- FFN,
- residual and LayerNorm flow,
- tabular deep-learning research direction.

Frame carefully:

```text
FT-Transformer bu veri büyüklüğü ve mevcut eğitim/çıkarım koşullarında XGBoost’u geçmemiştir; ancak kolonlar arası etkileşimleri attention mekanizmasıyla temsil edebilmesi nedeniyle ileri modelleme ve akademik mimari karşılaştırma açısından değer taşımaktadır.
```

## 6. PSO / Multi-Objective Optimization

The code now supports PSO for both:

- `xgboost`
- `ft_transformer`

The objective is not full Pareto MOPSO. It is a weighted scalarized multi-objective cost:

```text
J(theta) = w_rmse * RMSE/RMSE_ref
         + w_latency * T_inf/T_ref
         + w_size * S/S_ref
```

Default intended weights:

```text
RMSE:    0.70
Latency: 0.20
Size:    0.10
```

This means the report should say “weighted/scalarized multi-objective PSO” or “ağırlıklı çok hedefli PSO” rather than implying a full Pareto-front optimization unless the code is extended to true MOPSO.

Important files:

- `src/optimization/objective.py`
- `src/optimization/pso_search.py`
- `scripts/run_pso.py`
- `artifacts/pso/`
